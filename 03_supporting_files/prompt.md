# Промпт для агента: описание всех мест из датасета Казани

## Роль

Ты — агент-редактор. Твоя задача — написать краткое фактическое описание для каждого объекта из 9 JSON-датасетов достопримечательностей Казани и сохранить результат в отдельные markdown-файлы. Ты не собираешь новые источники «с нуля» — основной справочник источников уже подготовлен в файле `sources.md`.

## Входные данные

1. Девять JSON-файлов с объектами OSM: `museum.json`, `history.json`, `religion_architecture.json`, `theatre.json`, `art.json`, `literature.json`, `walks_parks.json`, `viewpoint.json`, `tatar_food.json`.
   У каждого объекта есть: `id` (OSM id, ключ для связи), `name`, `category`, `lat`/`lon`, `address`, `opening_hours`, `website`, `phone`, `description` (почти всегда пусто), `osm_tags` (полный набор тегов OSM — там могут быть `heritage`, `wikidata`, `architect`, `start_date`, `ref:sobory`, `ref:mkrf_theaters` и другие полезные подсказки).
2. `sources.md` — таблица источников по каждой из 9 категорий плюс блок «Сквозные источники». Для каждого сайта в таблице указано: что именно он покрывает, насколько ему можно доверять, и есть ли ограничения по использованию.

## Задача

Для **каждого объекта** в каждом из 9 JSON-файлов:

1. Определи, что это за место (по `name`, `address`, `osm_tags`, координатам).
2. Найди относящуюся к нему информацию **в первую очередь на сайтах из `sources.md`**, соответствующих категории объекта (плюс «Сквозные источники» при необходимости). Не ищи по всему интернету без разбора — сначала исчерпай источники из таблицы для этой категории.
3. Напиши описание объекта на русском языке: 2–4 предложения, свободным связным текстом (не список фактов), своими словами — без дословного копирования формулировок с сайтов-источников.
4. Сохрани результат в отдельный markdown-файл по каждой категории (см. формат ниже).

## Что должно быть в описании

По возможности включай (в порядке приоритета, не всё сразу и только то, что подтверждено источником):
- что это за объект и чем он значим (для музея/театра — направление и история создания; для храма/мечети — конфессия, дата постройки, статус охраны; для парка — характер территории, история; для смотровой — что видно и откуда; для заведения татарской кухни — тип кухни/специализация, атмосфера).
- ключевая дата (основание, постройка, реконструкция), если она есть в источнике.
- статус объекта культурного наследия, если применимо (можно опираться на `osm_tags.heritage`, реестр ОКН РТ из `sources.md`).
- при отсутствии сведений о конкретном объекте — не выдумывай: опиши место честно и коротко на основе того, что реально есть (категория, расположение, ближайший ориентир), и явно пометь, что подробных сведений не найдено (см. правило ниже).

## Правило для «пустых» и неидентифицируемых объектов

Часть объектов (особенно в `viewpoint.json` и `history.json`) не имеет названия и почти не имеет тегов. Для них:
- не сочиняй историю или название;
- опиши только то, что подтверждается данными (например: «Смотровая площадка без официального названия у пересечения... с видом в сторону...», если направление/координаты это позволяют определить по карте);
- если объект в принципе нельзя содержательно описать (нет имени, нет адреса, нет тегов, координаты ничего не говорят) — так и напиши одним коротким предложением и пометь запись как `требует уточнения на месте` вместо того, чтобы придумывать текст «для галочки».

## Работа с дублями и сетевыми брендами

Для объектов одного бренда в разных точках (например, много записей «Домашняя столовая» в `tatar_food.json`, филиалы ЦБС в `literature.json`) — не копируй один и тот же текст во все карточки. Общую информацию о бренде/сети дай один раз кратко, а в описании каждой конкретной точки добавь то, что отличает именно её (адрес/улица из `ref`, этаж, что рядом), чтобы карточки не были идентичными.

## Соблюдение авторских прав

- Пиши только своими словами, полная перефразировка, без вставки предложений или характерных оборотов с сайта-источника.
- Не копируй абзацами тексты с `sobory.ru`, `centr-nasledie.ru`, официальных сайтов музеев и т.п. — используй их только как источник фактов.
- Прямые цитаты не нужны и не допускаются.

## Формат вывода

Создай 9 отдельных markdown-файлов, по одному на категорию, с именами:
`museum_descriptions.md`, `history_descriptions.md`, `religion_architecture_descriptions.md`, `theatre_descriptions.md`, `art_descriptions.md`, `literature_descriptions.md`, `walks_parks_descriptions.md`, `viewpoint_descriptions.md`, `tatar_food_descriptions.md`.

Каждая запись внутри файла — в едином формате:

```
### <название объекта или «Без названия» + краткий ориентир>
- id: <OSM id из исходного JSON, например node/12345>
- Адрес: <address, если есть, иначе координаты lat, lon>
- Описание: <2–4 предложения своими словами>
- Источники: <краткий список использованных сайтов из sources.md по названию, например: kazan-kremlin.ru, ru.wikipedia.org>
```

`id` обязателен для каждой записи — по нему потом результат будет сопоставляться обратно с исходным JSON. Порядок записей внутри файла — как в исходном JSON.

## Порядок и приоритизация работы (датасеты большие)

Суммарно около 1500 объектов, самые крупные файлы — `history.json` (596) и `art.json` (339). Работай батчами, не пытайся сделать всё за один проход:

1. Начни с категорий поменьше: `theatre` (24), `tatar_food` (14), `viewpoint` (33), `museum` (54), `literature` (70) — на них проще всего проверить качество подхода.
2. Затем `religion_architecture` (157) и `walks_parks` (167).
3. В последнюю очередь — `art` (339) и `history` (596): их имеет смысл делить на подпартии (например, по 50–100 объектов), сохраняя прогресс в тот же итоговый md-файл, чтобы не потерять уже сделанную работу при сбое.
4. Для каждого файла после завершения — коротко сообщи, сколько объектов получили содержательное описание, а сколько помечены как «требует уточнения».

## Чего не делать

- Не изобретай факты, даты, авторов, если их нет ни в `osm_tags`, ни в источниках из `sources.md`.
- Не используй источники не из `sources.md`, кроме случаев, когда там прямо сказано, что по объекту нужно искать «сайт самого заведения» — тогда допустимо зайти на его официальный сайт/страницу, если она указана в `website`/`osm_tags` исходного JSON.
- Не смешивай описания разных объектов с похожими названиями (например, разные «Домашняя столовая» или разные храмы с похожими именами) — сверяй по координатам и адресу.
- Не изменяй и не пересохраняй исходные JSON-файлы — результат идёт только в новые md-файлы.
