# API: один успешный и десять негативных тест-кейсов

Источник: предоставленный frontend-api-reference.md. Это ожидаемые результаты по контракту, не отчёт о выполнении. URL окружения и код backend не предоставлены.

## Запуск

Импортируйте tourist_api.postman_collection.json в Postman, замените baseUrl на адрес тестового API. localhost:5000 — заполнитель, не обнаруженный сервер. Для P01 выставьте будущую дату рабочего дня музеев, загрузите очищенные места в БД и обеспечьте доступность LLM. Проверяйте ID ответа по БД и часы работы отдельно: HTTP-тест не может подтвердить их самостоятельно. Не запускайте safety-кейсы на обучающем endpoint: они предназначены для inference/валидации.

## Контракт и ограничения

- GET /health проверяет только процесс. Его 200 не доказывает работоспособность БД, LLM или TTS.
- GET /api/places/in-area не отдаёт name/address, но отдаёт description, imageUrl и categoryIconUrl. Для полноценной подписи метки нужен дополнительный контракт либо локальный справочник по id.
- POST /route-adventure: интересы и темп — закрытые перечни; aiRequest не заменяет структурированные параметры. Ограничение географии задаётся прямоугольником, а не административным полигоном.
- Отдельного endpoint перегенерации или routeId нет. Перегенерация — новый POST с обновлёнными userLocation, visitedPlaces, остатком durationMinutes и startAt.
- Haversine не проверяет мосты, заборы, закрытые дворы и доступные переходы. Нужен pedestrian routing по дорожному графу; никакой промпт не исправит эту гарантию backend.
- Время посещения музея и длительность спектакля — разные сущности. Афиша, бронирование и билетная доступность контрактом не представлены.
- voice-reading умеет только ru/tt и соответствующие голоса; возвращает WAV. Просьба о другом голосе не является атакой, но неподдерживаемый voice даёт 400.
- Для обучения различайте HTTP safety-отказ и текстовый ответ ассистента: текущий API возвращает общий message, без объяснения причины.

## Тест-кейсы

### P01. Культурный маршрут по Казани

`POST /route-adventure`

Ожидается **HTTP 200**. При исправных БД/LLM и наличии доступных мест возвращается согласованное расписание.

```json

  "durationMinutes": 180,
  "interests": [
    "история",
    "музеи"
  ],
  "pace": "обычный",
  "requiredPlaces": [],
  "visitedPlaces": null,
  "aiRequest": "Покажи музеи и исторические места Казани. Идём пешком по доступным дорожкам и мостам.",
  "userLocation": {
    "lat": 55.796127,
    "lon": 49.106405
  },
  "startAt": "2026-09-14T10:00:00+03:00",
  "optimizeVisitOrder": true
}
```

## Дополнительные проверки перегенерации (не входят в 11 HTTP-кейсов)

Эти проверки требуют управляемых фикстур БД/LLM или дорожного маршрутизатора. Нельзя гарантировать ошибку только текстом aiRequest. Для неправильного расписания контракт предусматривает 502, но конкретные детекторы необходимо проверить по реализации.

1. LLM вернула один ID дважды. Ожидание продукта: повтор не попадает в ответ; корректная перестройка либо контролируемый 502.
2. Одна достопримечательность представлена разными OSM ID. Проверять канонический ID, а не только равенство строк. Включать только одну остановку; не объединять разные филиалы сети.
3. Посещённая точка передана в visitedPlaces. Новый маршрут не возвращает её. При конфликте с requiredPlaces требуется согласованная политика: контракт приоритет не определяет.
4. Две точки разделены Казанкой. Проверить переход через доступный мост по дорожному графу; прямой отрезок над водой не является маршрутом. Текущий контракт эту гарантию не даёт.
5. Пользователь переместился после первого маршрута. Второй расчёт начинается от новых координат, а не первой точки старого маршрута.
6. Два запроса на перестройку завершились в обратном порядке. UI принимает только ответ последнего запроса; более ранний игнорирует. Отмена запроса не гарантирует отмену работы сервера.
7. Осталось 20 минут. Новый POST с durationMinutes=20 получает 400. UI сообщает о минимуме 30 минут и предлагает закончить прогулку; не увеличивает бюджет без согласия.
8. До закрытия музея 10 минут, визит занимает 60. Исключить/переставить музей либо вернуть контролируемую ошибку, не выходить за закрытие.
9. requiredPlaces содержит два далёких места и бюджет 30 минут. При невозможности построения — понятный отказ; не отрицательные времена и не превышение бюджета.
10. optimizeVisitOrder=false. Сохранить взаимный порядок обязательных мест; остальные точки можно вставлять, если это не нарушает расписание.
11. LLM вернула выдуманный ID, время задом наперёд или невалидный JSON. Backend отклоняет результат, ожидается 502; не выдавать частичный непроверенный маршрут.
12. LLM недоступна при перестройке. Сохранить предыдущий маршрут в UI и показать ошибку; ограничить повторы. Сам факт сохранения старого маршрута — требование UI, а не текущего HTTP-контракта.

## Что отдельно согласовать с backend

Сопоставление девяти категорий датасета с десятью interests; значение type; канонические ID достопримечательностей; приоритет required/visited; формат передачи посещённых ID; обработка закрытых/частных объектов; часы работы и афиша; дорожная геометрия; типизированные причины отказа; различие safety-фильтра и нейтрального обсуждения религии.
